Claude Code 使用笔记(6)_
一个插件，把散装零件装成整车

2026 · May Claude Code · claude-code-setup · 插件

大多数人用的 Claude Code 是"原生版"——装好就用，不加插件，不加配置。能用，但体验说不上好。

写代码靠临时起意，格式化靠运气，安全检查靠自觉。就像买了一台裸机，没装任何软件，然后说"这电脑也不怎么样"。

Anthropic 悄悄发了一个官方插件来解决这个问题：claude-code-setup。它不写代码，只做一件事——扫描你的项目，然后告诉你还缺什么。

它做了什么

装好之后，在 Claude Code 里说一句"帮我推荐自动化配置"，它会扫描整个项目：

- 看你的技术栈（React？Python？Go？）
- 看你的目录结构（monorepo？单项目？）
- 看你的配置文件（有 ESLint 吗？有测试框架吗？）

然后从五个维度给出推荐：

MCP Servers — 外部工具集成。前端项目推 Playwright 做自动化测试；文档不全的项目推 context7 做文档查询。

Skills — 打包好的专业能力。复杂项目推 Plan agent 做架构规划；前端项目推 frontend-design 做界面生成。

Hooks — 自动化触发器。没配 linter 的项目推自动格式化 Hook；有敏感文件的项目推文件保护 Hook。

Subagents — 专项审查代理。推安全审查、性能审查、可访问性审查三个专用 agent，各管一摊。

Slash Commands — 快捷指令。/test 一键跑测试，/pr-review 一键做 PR 审查，/explain 一键解释代码。

每个维度只推 1-2 个最相关的，不堆数量。

为什么原生版不够用

Claude Code 的核心能力是对话和代码生成，但真正高效的开发环境不止这些。

Hooks 解决的是可靠性问题——格式化、lint 这些机械操作，靠人记着不靠谱，靠 AI 记着更不靠谱。系统级触发才是唯一的确定性方案。

Skills 解决的是深度问题——通用对话什么都能聊，但特定领域（架构设计、前端 UI）需要结构化的专业知识，Skills 就是把这个打包好。

MCP Servers 解决的是边界问题——Claude Code 跑在终端里，要访问浏览器、数据库、外部 API，就得靠 MCP 协议桥接出去。

Subagents 解决的是审查问题——自己写的代码自己查，跟考试自己批卷一个效果。独立 agent 只做审查，没有利益冲突。

这四样东西，原生版全都没有。不是它不好，是它只负责核心能力，生态的事留给插件。

和手动配置的区别

不用插件也能把这些配起来——手动写 settings.json、手动写 Hook 脚本、手动找 MCP server。但有两个问题：

第一，你得知道缺什么。很多人根本没意识到 Hooks 的存在，更不知道 formatting Hook 能解决什么问题。

第二，你知道缺什么也不一定知道怎么配。MCP server 的配置格式、Hook 的 matcher 写法，门槛不低。

claude-code-setup 是先告诉你缺什么，再帮你配好。两步都做了，而不是只做一步。

安装

一行命令：

/plugin install claude-code-setup@claude-plugins-official

然后对 Claude Code 说"帮我推荐自动化配置"。剩下的它会引导你一步步完成。

Claude Code 的真正能力不在核心里，在它周围的生态上。不装插件是自行车，装了才是机动车～
